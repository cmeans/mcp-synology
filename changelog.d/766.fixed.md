- **`create_download` refuses sources on the NAS or its local network** (#766): **Security:** Download Station fetches each URI from the NAS, and it fetched every loopback spelling (`127.0.0.1`, `localhost`, `[::1]`, `2130706433`, `127.1`, `0.0.0.0`, a `thunder://` link wrapping one) and accepted `169.254.169.254` on DSM 7.1, 7.2.2, 7.3.2 and 7.4.1, so a prompt-injected source could make the NAS fetch its own admin interface, its LAN or a cloud metadata service. Now a URI naming a loopback, private, link-local, CGNAT, multicast or unique-local address in any spelling, a local name (`localhost`, `.local`, `.lan`, `.internal`, `.home.arpa`, a name with no dot and the other private names RFC 6762 lists) or the NAS's own host from the config (`connection.host`) is refused before anything is sent, inside magnet trackers, ed2k links and `thunder://`, `flashget://` and `qqdl://` links too; a link that can't be read is refused as one that can't be checked. The new Download Station setting `allow_local_addresses` (default `false`) lets them through, for downloads from your own network. Not caught: a public name that resolves to an internal address, a redirect to one, another name or address for the NAS, and a `.torrent` file's trackers (#765). DSM's error 1901 now reads "Unsupported source URI", and `create_download` is annotated `openWorldHint` — closes #648
