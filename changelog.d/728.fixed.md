- **`create_folder` names the folders it created before a later path failed** (#728): the folders are created one request at a time, and a refusal of a later path (DSM's error, or #702's under-a-file refusal) left the earlier ones on the NAS while the error named only the failing path, so a model read it as nothing created; a request with no answer (a timeout, a proxy's error status or a reply that isn't DSM's) on a later path didn't name them either. The error now names the path that failed (`Failed on:`, when DSM's error doesn't), the folders `Already created before this failure:` and the paths `Not started:`, as the batch tools' failures do (#482), and says a path with no answer may have been created (one whose connection was never made wasn't). With `force_parent=false` it isn't retryable once something was created or a path got no answer, and the advice says to leave the created folders out (and to check a path that may have been created with `list_files`); with `force_parent` (the default) an existing folder isn't an error, so the error's own retryable flag stands. A success reply that names no folder now counts the path asked for (`Created 1 folder(s):`, not 0) — closes #713
