- **Secrets in some URLs reached Download Station replies and DEBUG logs** (#680, #514): a password holding a `/` (`https://user:pw/d@h`) or a `#`, which cut the URL short so the start of the password showed, a `thunder://`, `flashget://` or `qqdl://` link (which encode a whole URL, credentials included), and a token after a comma followed by a scheme-like word (`files=a,b://c&token=…`, `ftp://h/a,ED2K:foo?token=…`) were shown as they were. They're masked now, and `&key=value` that lost its `?` in a path is masked as a query item. A list, set or dict value in a DEBUG request log is redacted item by item too, with bytes decoded and parameter names compared case-insensitively (today's URI lists go as one string, which was redacted already). A user name with a backslash that isn't a JSON escape (`CORP\jdoe:pw@ftp.example`) has the whole authority masked (`ftp://***/x`): a browser reads the backslash as `/`, so which part is the host isn't clear — closes #466 and #458's `_log_safe` list item. A password holding a space still isn't masked: a URL can't hold one (RFC 3986), as secret scanners such as detect-secrets and Sentry Relay also assume, and reading past it read prose and JSON as userinfo
