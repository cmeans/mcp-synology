- **Local paths in refusals, the LOCAL PATHS instructions and tool descriptions are quoted like other local paths** (#712): the refusal every tool with a local path gives for one outside the allowed folders (`upload_file`, `download_file`, `upload_photos`, `download_photos`, `create_download`) wrote the caller's path, the path a link resolves to and the allowed folders raw, the folders joined with `, `, so a tab or padding didn't show and a folder named `a, b` read as two; so did the instructions' LOCAL PATHS and the local-path parameters' descriptions, and `create_download`'s refusals and reply for a `.torrent` file (its refusals with `!r`, which doubles a Windows backslash). Each is now written as `upload_file` and `download_file` write a local path since #698 (`shown_local`: quoted whole when a part needs it), the folders one a line in the refusal and the instructions; a description, which can't take lines, relies on the quoting. A path that can't be resolved no longer repeats the error's own copy of it (on Python 3.11 and 3.12, a symlink loop is now `a symlink loop` and a chain of links too long to follow `too many symlinks to follow`), and a loop or chain that leads outside the allowed folders (followed as far as its links can be; the first link that can't be followed, and a `..` after it, counted where they're spelled) is refused as outside (`permission_denied`, as any other), so the reply no longer shows that a loop exists there. A NUL byte is still `invalid_parameter` wherever the path is. A config entry `allowed_local_paths` refuses, and LOCAL MACHINE's `Home directory:` line (before, quoted only for a control character or line break), are written the same way, and LOCAL MACHINE now says a local path can be shown in quotes in these instructions or a tool's description too. `shown`, `shown_local` and the Unicode rules they use moved from File Station's helpers to `core/display.py`, so `core` can use them — closes #697
